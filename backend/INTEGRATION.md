# 与 Gemini 的联调说明

契约版本：0.2.0。后端已实现40个操作。保留原有38个操作，新增游戏角色缓存与刷新接口；前端已同步补齐签到福利入口。新增字段与人工验证目的见 [接入说明](../docs/game-checkin.md)。

## 对 frontend/API-QUESTIONS.md 的答复

### 1. activeCredentialOperationId

实际后端在读取 Account 时，从持久化操作记录重新计算活动指针。只有 queued、running、awaiting_verification 视为活动操作；succeeded、failed、canceled 均不再返回该指针。终态操作的 GET 响应中 account.activeCredentialOperationId 也为 null。

前端指出的模拟数据有共享对象导致的遗留活动指针，已在共享场景文件中修正。前端对终态操作的防御性处理可以保留。

### 2. submit-code 的状态码

`POST /login-flows/{flowId}/submit-code` 在正常受理时统一返回 HTTP202，包括 awaiting_captcha、exchanging、completed。错误使用契约的错误响应。前端仍需以 data.state 与 nextAction 决定交互，不需要补充200响应。

当前服务可能在单次请求中完成登录与凭据交换并直接返回completed。接口已支持后续查询，不需要为了模拟异步人为延迟。

### 3. Run 的账号展示

沿用当前契约：Run 只保存 accountId。前端通过账号列表映射昵称与脱敏手机号；历史账号删除或不在缓存中时显示 ID 摘要。无需新增字段。

## 额外的行为说明

- 默认地址为 http://127.0.0.1:3000/api/v1，前端Vite代理配置已与此一致。
- 首次初始化需要本机backend/.env中的BOOTSTRAP_TOKEN，由实例所有者在UI输入；不提供公开获取该token的接口，也不需要把它交给Gemini。
- 管理员会话与米游社账号登录不同。401回面板登录；ACCOUNT_REAUTH_REQUIRED提示重新登录相应米游社账号。
- 人机验证 renew 创建新的本地 challengeId 与组件，沿用当前官方验证会话的剩余窗口，不自动重新发短信。窗口已过期返回410；重新开始原登录或任务操作。不会假装延长官方session寿命。
- 人工验证只有在用户完成官方SDK后才提交结果；模拟模式的占位验证结果不能提交到真实后端/官方接口。
- 原神社区签到与游戏签到福利可执行；游戏签到按绑定角色处理，不受社区签到列表中星穹铁道“待适配”的限制。真实GT3签到验证尚未实测，不能宣称所有类型已验证。
- 后端每6小时对启用且autoRefresh的账号做一次健康检查，工作Cookie临近保存期限时尝试获取；已要求重新登录或正在等待验证的账号不会循环自动重试。全局暂停调度同时暂停周期扫描，手动操作仍可执行。
- 业务POST/DELETE要带Idempotency-Key；验证码更正、重新完成验证等新意图使用新key。相同key回放的是原请求快照，查询资源才能取得最新状态。
- 没有请求体的动作无需强行发送{}；若发送空对象也可，不能夹带额外字段。
- 缓存任务GET不请求上游；刷新任务POST才请求。首次没有快照时fetchedAt与余额字段为null。

## 本轮验证范围

Node.js24 LTS下17组自动化测试通过；测试中遍历了全部38个操作，响应逐项通过共享OpenAPI schema校验。覆盖虚构A/B隔离、密文跨账号拒绝、人工验证、短信幂等、前导零、凭据失效、错误账号重新登录、重复签到、未知写入不重放、跨日调度、重启、在线备份及写请求进行中取消后保留真实结果。

自动化测试使用虚构账号，不发送真实短信、签到或邮件。2026-10-26另行通过正式后端API完成单账号原神、星穹铁道、绝区零的真实游戏签到和状态复核；实际奖励及尚未实测的范围见签到福利接入说明。前端入口已通过演示模式的完整交互检查。

本机当前没有Docker命令，部署文件尚未在容器中实跑；不能把本地构建通过当作Docker部署已验证。
