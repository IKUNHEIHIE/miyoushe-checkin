# 签到福利接入说明（契约 v0.2.0）

2026-10-26 新增：首页“签到福利”所对应的游戏奖励签到。它与社区签到领取米游币是两类独立任务，可同时启用，也可单独执行。前端这次已同步接入，不需要 Gemini 另做一次实现。

## 使用

首页“签到福利”入口 → 账号详情 → 刷新游戏角色 → 启用签到福利 → 选择全部角色或指定角色 → 保存签到设置。点击“保存并立即签到福利”可单独执行游戏签到；顶部“立即执行选定任务”和账号批量执行沿用账号任务偏好。

开启账号每日计划后，执行器每天按照已保存的 `taskKinds` 与 `gameRoleIds` 执行。新账号的每日计划仍默认关闭；升级不批量改动其他部署者的账号配置。

## HTTP 变更

- `GET /api/v1/accounts/{accountId}/game-roles`：仅查询缓存，不访问上游。未获取时返回空角色列表、`fetchedAt=null`、`stale=true`。超过15分钟或跨北京时间日期后标记过期。
- `POST /api/v1/accounts/{accountId}/game-roles/refresh`：查询官方绑定角色、签到状态和奖励列表；要求管理员会话、CSRF、Idempotency-Key；账号忙时返回409。
- `Account`、`AccountPatch`、`RunRequest`、`Run` 新增可选 `gameRoleIds: string[]`。空数组表示所有当前可执行的绑定角色；每日运行时重新读取角色绑定，因此也包括以后新增的角色。非空数组表示固定选择。
- `TaskKind` 新增 `game_sign`；`Challenge.purpose` 新增 `game_sign`。旧的 `community_sign` 含义不变。
- 游戏任务按角色展开步骤，`RunStep` 新增 `gameRoleId`、`gameName`、`roleLabel`、`rewards[]`。一个游戏多个角色会独立签到。
- 游戏任务不受社区签到能力目录中 `communities[].executable` 的限制；`communityIds` 仅用于社区任务。仅执行游戏签到时可传空数组。
- `Capabilities.games[]` 列出已配置的游戏适配器。任务可执行性与真实实测范围需要分别理解。

示例：先保存账号偏好启用 `game_sign`，再创建运行：

```json
{
  "communityIds": [],
  "taskKinds": ["game_sign"],
  "gameRoleIds": []
}
```

客户端只提交后端签发的角色 ID；UID、区服与游戏类型从该账号自己的官方绑定列表读取，不接受客户端指定任意签到目标。

## 判定与恢复

执行前查询角色的 `is_sign`。已签到则跳过写入，记为 `already_completed`，不重复计算奖励。发送签到后再次查询，确认 `is_sign=true` 才记录成功。游戏物品写在 `steps[].rewards`，不会加入 `confirmedRewardPoints`；后者始终只统计米游币。本项目复核的是官方签到状态和奖励记录，未验证游戏内背包或邮件实际入账。

官方 `retcode=0` 但 `data.success=1`、同时包含极验信息时，表示需要人工验证。沿用面板验证弹窗；用户完成后恢复对应角色。没有自动解题、第三方打码或绕过验证。`-5003` 也必须复查状态，不能直接当作成功。

每日唯一键为账号、北京时间业务日期、游戏、任务种类与角色 ID；同游戏多角色不会互相抢占。写入超时先查询确认；无法确认则 `outcome_unknown`，后续重试只核对，不盲目重发。服务重启与取消沿用原执行器的持久化恢复逻辑。跨零点的写入不归算到旧日。

2026-10-26 单账号实测：原神累计签到4→5天，奖励甜甜花酿鸡×3；星穹铁道3→4天，奖励罐装快乐水×1；绝区零0→1天，奖励正式调查员记录×2。三个步骤经官方查询复核为已签到；同日重复创建相同运行返回已有记录。未在本文保存账号ID、UID、Cookie或验证码。
